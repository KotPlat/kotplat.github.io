roomQL

A type-safe Kotlin DSL for building dynamic Android Room queries at runtime — no raw SQL strings, no reflection, and no 2ⁿ DAO methods.

InstallQuick startAPI overviewFAQ
When query structure changes at runtime, roomQL keeps the moving parts typed.
Build filters, sorting, joins, grouping, and projections with Kotlin references instead of assembling unchecked SQL strings.

Installation

roomQL is published on Maven Central under io.github.kotplat.roomql. Add the runtime, Android bridge, and KSP processor you need.

[versions]
roomql = "2.0.0"

[libraries]
roomql-runtime-android = { module = "io.github.kotplat.roomql:runtime-android", version.ref = "roomql" }
roomql-ksp-processor = { module = "io.github.kotplat.roomql:ksp-processor", version.ref = "roomql" }
plugins {
    id("com.google.devtools.ksp")
}

dependencies {
    implementation(libs.roomql.runtime.android)
    ksp(libs.roomql.ksp.processor)
}

Quick start

Generated table references keep columns typed while optional values can disappear from the query when they are null.

fun searchUsers(dao: UserDao, minAge: Int?, status: String?): List<UserEntity> {
    val q = query {
        from(UserEntityTable)
        where {
            UserEntityTable.age gteIfNotNull minAge
            UserEntityTable.status eqIfNotNull status
        }
        orderBy(UserEntityTable.age, SortDirection.DESC)
        limit(20)
    }
    return dao.search(q.toQuery())
}

API at a glance

SymbolPurpose
query { }Entry point for building a RoomQlQuery.
from, join, whereDefine the query source and conditions.
orderBy, groupBy, limitControl dynamic result structure.
eqIfNotNull, gteIfNotNullSkip optional conditions when values are null.
toQuery()Adapt the result for Room's @RawQuery.

What you get

  • Typed dynamic structure. Sort, group, join, and select with real Column<T> references.
  • Compile-time column safety. Renames and typos fail during the build.
  • Bound values. Values are emitted as positional parameters instead of interpolated SQL.
  • Plain JVM testing. The runtime produces SQL and arguments without requiring an emulator.

FAQ

Does roomQL replace Room?

No. roomQL sits on top of Room and produces the SupportSQLiteQuery accepted by Room's @RawQuery.

Does roomQL use reflection?

No. The KSP processor generates typed table and column references at build time.

Does it support Kotlin Multiplatform?

Not yet. The runtime is currently a plain JVM module and the Android bridge targets Room.

Is it safe from SQL injection?

Values are bound as positional parameters. Dynamic identifiers come from typed column references rather than user-provided SQL strings.
